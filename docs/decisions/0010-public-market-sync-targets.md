# 0010: 公共行情同步目标持久化与私人资产本地事实来源边界

日期：2026-07-23

## 状态

Accepted

2026-07-23 由产品负责人确认。

## 背景

当前根目录静态 MVP 以浏览器 `localStorage` 中的 asset snapshot 作为私人资产唯一事实来源。行情 API 可以按公共证券代码抓取并缓存价格，但此前不会持久化用户请求过的代码，因此用户关闭页面后，服务端每日任务只能更新系统分析基准，不能继续维护用户下次打开页面时需要的公共行情。

资产首次历史回补此前还受固定 365 天窗口限制，分析基准也不能稳定覆盖组合最早持有日期。上述行为会造成价格和基准缓存落后，增加用户打开产品后的等待时间，并损害数据可信感。

## 决策草案

引入不关联用户的公共行情同步目标集合 `market_data_sync_targets`：

- 保存公共证券代码、市场、来源类型和同步状态；
- 不保存 `userId`、资产 ID、数量、成本、账户、资产名称、交易、备注或精确持有日期；
- 用户请求行情时，把代码登记为 `user_requested`；
- 系统分析基准登记为 `benchmark`；
- 每日计划任务读取全部 `user_requested` 目标，并与全部系统分析基准合并、去重后增量同步；
- PostgreSQL 是线上持久化来源，本地开发可以回退到 `storage/market-data/sync-targets.json`；
- 代码集合仅用于维护共享公共行情缓存，不作为用户持仓、资产所有权或兴趣标签的事实来源。

私人资产的唯一事实来源继续是浏览器本地 asset snapshot。该决策不启用完整资产云同步，也不改变数量、成本、账户、交易、复盘和设置的本地保存边界。

## 历史覆盖规则

- 每个资产从自身最早持有日期到今天确保公共历史行情覆盖；浏览器只发送由本地日期计算出的历史窗口天数，不发送精确持有日期。
- 全部分析基准从组合最早持有日期到今天确保覆盖。
- 已有缓存只补首端或尾端缺失区间，不重复抓取完整历史。
- 外部数据源存在单次条数限制时，按连续日期区间分段抓取。
- 非交易日不制造市场收盘价；缺失、失败和前值延续继续保留明确状态。

## 更新触发规则

1. 新增或修改资产代码、最早持有日期时，立即确保资产与全部分析基准的历史覆盖。
2. API 每日计划任务统一更新已登记代码和全部分析基准。
3. 用户手动同步时，更新本地全部资产代码和全部分析基准，并修复发现的历史边界缺口。
4. 页面每日首次打开时继续进行覆盖检查，作为计划任务失败或缓存滞后的兜底。

## 原因

- 用户关闭页面后仍可维护公共行情，减少下次打开时的等待。
- 不需要上传完整资产对象，也不需要把 Database 变成私人资产事实来源。
- 公共代码不与用户身份关联，降低当前种子阶段的隐私和鉴权复杂度。
- 独立同步目标表比复用运行日志或实验性 `user_assets` 表更清晰、可审计、可迁移。

## 备选方案

### 从 `market_data_runs.requested_symbols` 汇总代码

不采用。审计日志不应成为调度事实来源，长期扫描成本、状态表达和清理边界都不可靠。

### 启用 `user_assets` 和完整私人资产云同步

不采用。当前尚未完成服务端真实身份验证、用户隔离、同步冲突、删除、导出和恢复闭环，且超出本次公共行情维护范围。

### 按用户保存证券代码订阅

当前不采用。它可以支持精确注销和用户级管理，但需要真实鉴权、用户隔离、删除和隐私控制。正式启用私人资产云同步时重新评估。

## 数据与隐私后果

- 服务端会长期保存曾被登记为公共行情同步目标的证券代码和市场。
- 服务端不能从该表判断哪个用户持有某个标的，也不能确定代码代表持仓、历史持仓或仅一次查询。
- 用户删除本地资产后，当前无法精确注销其对应代码；继续同步只增加公共行情维护成本，不暴露用户资产关系。
- 产品说明和 API Contract 必须明确代码会被保存为不关联用户的公共行情目标。

## 迁移与回滚

- 新表为附加表，不修改现有公共价格主键或私人资产结构。
- 回滚应用版本后可以停止读取该表；已抓取的公共价格可以保留。
- 如需删除新表，必须先停止依赖它的每日任务，并备份同步目标状态。
- 不使用用户资产备份覆盖或恢复公共行情表。

## 重新评估条件

- 正式启用带真实身份验证的资产云同步；
- 需要在用户删除资产时精确停止对应行情订阅；
- 同步目标数量导致公共接口成本或限流不可接受；
- 需要按用户、套餐或权限控制行情覆盖；
- 数据源授权不允许以共享缓存方式维护用户请求标的。

## 待批准事项

- 是否接受服务端长期保存不关联用户的公共证券代码同步目标；
- 是否接受用户删除本地资产后，当前版本不精确注销公共同步目标；
- 是否接受 PostgreSQL 作为线上同步目标持久化前提。
