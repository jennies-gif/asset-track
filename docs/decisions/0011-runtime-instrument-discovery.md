# 0011: 运行时公共资产发现、验证与资源库补录边界

日期：2026-07-25

## 状态

Draft

已由产品负责人授权按推荐工程方案实施并起草，尚未批准为 Accepted。

## 背景

新增资产时，服务需要在资源库已有记录时自动补齐代码、名称、市场、类型和币种；资源库未命中时，还需要尝试确认公共资产是否真实存在并降低手动维护价格的成本。

此前 API 会根据代码格式推测市场和类型，并在取得公共行情前写入资源库。代码格式只能形成候选，不能证明资产真实存在，可能污染公共主数据。把用户输入的任意自由文本名称自动转发给第三方搜索服务，也可能扩大当前私人数据传输边界。

## 决策草案

- 服务端资源库仍是公共资产检索的第一来源。
- 资源库未命中时，只对当前支持范围内的标准化公共代码建立临时候选。
- 临时候选必须取得有效公共价格后才能写入资源库；抓取失败、价格缺失或代码无效时不得补库。
- 运行时补录记录必须保留来源、来源更新时间、行情支持状态和审计事件。
- PostgreSQL 是线上公共资源库事实来源；未配置数据库的本地开发环境使用现有 JSON fallback。线上写入不同时依赖本地 JSON 成功。
- 自由文本名称未命中资源库时，不自动转发给第三方数据源。当前无法验证时允许用户继续手动保存，并明确显示未检索到公共资产或价格。
- 精确持有日期、买入价格、数量、账户和备注继续只保存在浏览器本地。
- 历史买入价查询只向行情 API 发送公共代码和由本地日期计算的 `days`；浏览器在本地选择请求日期当天或此前最近有效交易日价格。

## 备选方案

### 按代码格式直接补库

不采用。实现简单，但会把不存在或分类错误的代码写成公共主数据。

### 把任意名称自动发送给第三方搜索

当前不采用。覆盖更广，但自由文本可能是私人标签，需要额外的数据告知、授权和第三方边界评估。

### 上传精确持有日期，由服务端返回买入价

不采用。会改变当前已经批准的私人资产本地保存边界。

## 数据与隐私影响

- 服务端只保存经过验证的公共代码、名称、市场、类型、币种和公共来源信息。
- 公共代码可以按 ADR 0010 登记为不关联用户的行情同步目标。
- 不新增用户、资产 ID、持有日期、成本、数量、账户或备注的服务器存储。
- 未改变私人资产本地快照的事实来源。

## 兼容、迁移与回滚

- 新增的成本价格来源字段是本地资产快照的可选字段；旧快照缺少这些字段时按手动或缺失状态兼容，不要求破坏性迁移。
- 回滚应用版本不会改变已有私人资产字段的核心含义；新增公共资源记录可以保留。
- 如需撤销运行时发现，应停止新补录逻辑，不删除已有公共资源或价格数据；生产清理需要另行审批。

## 风险与重新评估条件

- 外部数据源的覆盖、授权或限流可能导致真实代码暂时无法验证。
- 名称搜索覆盖不足时，继续依赖资源库周期同步和手动录入兜底。
- 需要把自由文本名称发送给第三方、增加新市场或改变公共数据授权时，重新评估本决策。
- 正式启用私人资产云同步时，重新评估历史价格查询和成本来源字段的服务端边界。
