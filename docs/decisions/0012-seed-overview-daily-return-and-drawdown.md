# 0012: 种子版总览昨日收益与最大回撤边界

日期：2026-07-28

## 状态

Draft

## 背景

总览原先把每项当前价格与上一交易日价格直接相减，并要求组合内所有资产的最新行情日期完全一致。跨市场、基金和数字资产的价格日期经常不同，因此一个正常的多市场组合会长期显示“最近交易日收益暂无法计算”。

总资产趋势同时基于当前仍持有的资产及当前数量重建整段历史，再据此计算最大回撤及主要回撤资产。清仓会把资产从重建序列中移除，导致过去的回撤解释随当前持仓变化。这一结果不能可靠表达组合历史收益回撤。

## 决策

### 昨日收益

- 总览使用用户当前日期的前一完整自然日作为“昨日”，比较昨日与前一自然日的组合行情变化。
- 股票、ETF、基金等非交易日使用已经缓存并明确标记为顺延的最近可用日线。
- 使用昨日开始时可重建的持仓数量；今日发生的清仓不会从昨日收益中移除该资产。
- 如果昨日发生买入、加仓、卖出或清仓，当前种子版不尝试估算盘中资金流影响，明确显示暂无法计算。
- 任一昨日持仓缺少昨日或前一日价格时，不静默排除该资产，明确显示行情尚未齐备。
- 跨币种资产暂按当前设置汇率折算，界面明确标记为估算，不表达为已经包含昨日汇率变动的完整收益。

### 最大回撤

- 种子版总览暂时不展示最大回撤及主要回撤资产。
- 现有估算趋势仍可用于观察资产余额变化，但不作为现金流调整后的收益序列。
- 只有在能够基于历史持仓、交易现金流、日价格和日期对应汇率生成可复算的组合收益序列后，才重新引入最大回撤。

## 选择原因

- 避免把跨市场行情日期差异误表达为无法提供任何日变化信息。
- 避免把清仓、投入和提现造成的余额变化误表达为投资收益回撤。
- 保持种子版范围可控，不在上线前引入完整的每日组合估值账本。
- 缺失或无法准确剔除的数据继续显式降级，不静默生成看似精确的结果。

## 备选方案

### 保留“最近交易日收益”

不采用。该口径要求所有资产共享同一最新行情日期，与多市场组合的正常数据状态冲突。

### 立即建设完整每日组合收益账本

暂不采用。该方案需要重建每日持仓、交易现金流、价格、汇率和估值序列，影响范围超出当前种子版最小安全修复。

## 数据和隐私影响

- 私人资产、交易和持仓数据仍以当前浏览器本地数据为事实来源。
- 不新增私人数据上传，不改变公共行情请求字段。
- 不改变 API、Database 或当前 local-first 边界。

## 兼容与迁移影响

- 不修改主持久化 schema、版本、导入导出或恢复格式。
- 复用现有资产 `dailyPrices`、`buyRecords`、`sellRecords` 和行情来源字段。
- 旧数据缺少日线或交易明细时显示不可计算原因，不自动填造数据。

## 风险

- 跨币种昨日收益暂按当前汇率估算，不能反映昨日汇率变动。
- 昨日存在交易时不会显示估算收益，覆盖率低于完整收益账本。
- 日线缓存缺失会继续导致单日收益暂不可用。

## 回滚方式

- 恢复原总览指标渲染和原“最近交易日收益”选择器。
- 删除新增的昨日收益领域计算模块及对应测试。
- 恢复最大回撤摘要展示；回滚后仍需保留其当前口径限制说明。

## 重新评估条件

满足以下任一条件时重新评估完整组合收益序列：

- 种子用户明确把现金流调整后的日收益或最大回撤视为高频核心价值；
- 当前不可计算状态明显阻碍组合维护；
- 已具备稳定的历史持仓、交易现金流和日期对应汇率数据；
- 需要在总览、分析和复盘之间复用同一套历史收益口径。
