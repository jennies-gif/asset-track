## 2. 产品气质

### 2.1 核心定位

Asset Trail 的目标体验是：

> 安静、可信、克制、可审计的个人资产工作台。

英文工作定义：`Quiet Financial Workspace`。

用户进入产品后，应感到自己正在使用一套成熟的个人金融工具，而不是营销页面、行情终端、游戏化理财应用或由模板拼成的 AI Dashboard。

### 2.2 品牌关键词

- 清晰：用户能迅速理解总资产、分布、变化和下一步；
- 可信：来源、时间、缺失、手动和估算状态真实可见；
- 冷静：不制造追涨杀跌、收益焦虑或交易冲动；
- 成熟：视觉规则稳定，组件行为可预测；
- 私密：私人资产默认不公开，金额可隐藏，数据边界表述准确；
- 有温度：通过解释和恢复路径降低焦虑，不依赖卡通插画或拟人化表达。

### 2.3 非目标气质

Asset Trail 不应呈现为：

- 高饱和蓝紫渐变的科技模板；
- 每个区块都是圆角卡片的 Bento Dashboard；
- 强红绿刺激、闪烁更新的行情软件；
- 大量徽章、图标和空洞洞察组成的 AI 玩具；
- 过度生活化、卡通化的记账应用；
- 大面积营销口号、收益承诺或投顾入口。

### 2.4 参考产品的使用边界

可以学习 Wealthfolio、Codex / ChatGPT 和 OKX Web3 等成熟工具的：

- 连续画布与单一视觉主角；
- 总资产、趋势、账户和持仓的清晰优先级；
- Codex 式纯白主画布、极浅中性灰侧栏和清晰选中态；
- OKX 式黑白品牌识别、高对比操作和专业金融信息密度；
- 图表使用清晰、明亮、可区分的分类色，页面主体保持黑白中性；
- 全局账户范围、时间范围和金额隐藏；
- 问题集中到数据健康入口，并提供直接修复路径。

不得直接复制其品牌色、字体、图标、插画、组件代码或超出当前阶段的产品功能。

## 3. 设计原则

### 3.1 每个页面只有一个视觉主角

页面必须先回答一个核心问题，例如：

- 总览：我的整体资产现在是什么状态；
- 资产：我持有哪些资产，数据是否完整；
- 分析：这段时间为什么发生变化；
- 复盘：当时的判断和后续结果是什么。

同一视口内最多出现 1–2 个超大数字。次级指标不得通过相同字号、边框、底色或按钮权重与核心信息竞争。

### 3.2 一个页面只有一个主操作

每个页面或明确任务步骤最多一个 Primary Action。其他操作使用 Secondary、Ghost、Text 或 Overflow。

例如，总览页主操作可以是“添加资产”；“检查价格”“设置”“导出”“隐藏金额”不得同时使用主按钮样式。

### 3.3 连续画布优先于卡片堆叠

页面层级按以下顺序组织：

```text
Canvas
  → Section
    → Surface（仅在需要独立边界时使用）
      → Component
```

规则：

- 留白、对齐和分隔线是主要分组手段；
- 同一区域最多出现一层带边框 Surface；
- 禁止 Card 套 Card；
- 指标默认不是 Card；
- 只有重复实体、独立交互单元、可折叠内容或需要独立状态的区域才使用 Card；
- 首屏主要 Surface 原则上不超过 3 个。

### 3.4 可信状态就近表达

价格来源、更新时间、缺失、过期、手动、估算和同步失败应靠近受影响的数据展示。

全局区域只展示摘要，例如“4 项数据需要检查”，详细原因进入数据健康或对应资产。不得在顶栏、主卡片、区块说明和页脚重复同一段隐私或行情说明。

### 3.5 工具密度与可读性平衡

桌面端保持金融工具所需的信息密度，表格和紧凑列表优先；移动端按任务优先级折叠信息，不把桌面布局简单压缩成狭窄列。

### 3.6 视觉语义不得替代事实

- 不用绿色把估算值伪装成正常值；
- 不用红色表达所有异常；
- 不把缺失数据画成零；
- 不把演示历史、推导历史或成本价兜底表现为真实行情；
- 重要状态必须同时使用文字、图标或符号，不能只依赖颜色。

### 3.7 当前视觉冻结的实施边界

当前已确认的视觉升级属于“换肤与统一”，不是页面重构。未经单独确认，不得：

- 移动、增删、合并或拆分现有功能模块；
- 改变模块尺寸关系、信息顺序、操作入口或响应式结构；
- 修改文案逻辑、数据口径、交互流程或业务功能；
- 将概念图中的示意布局直接视为实现要求。

当前允许调整的范围是：颜色 Token、字体呈现、字重、边框、圆角、阴影、图表色值和不改变几何尺寸的状态反馈。任何布局或功能变化必须建立独立任务并由产品负责人确认。

## 4. Token 架构

所有长期视觉值采用三层 Token：

```text
Primitive Token（基础值）
  → Semantic Token（用途）
    → Component Token（组件）
```

示例：

```css
--neutral-950: #111111;
--color-action-primary: var(--neutral-950);
--button-primary-bg: var(--color-action-primary);
```

规则：

- 页面和组件优先使用 Semantic 或 Component Token；
- Primitive Token 不直接散落在组件选择器中；
- 不在页面 CSS 中新增未经批准的十六进制颜色、字体栈、圆角或阴影；
- 深色模式通过替换 Semantic Token 实现，不复制组件样式；
- Token 名称描述用途，不描述某个页面或短期视觉效果。

## 5. 色彩系统

### 5.1 品牌方向

正式品牌采用：

> 纯白主画布 + 极浅中性灰侧栏 + 黑色品牌交互 + 明亮数据色。

品牌识别和主操作采用黑白中性色，不设置蓝色或其他彩色品牌主色。蓝、绿、橙、紫和红只用于图表分类、正负结果、状态和少量信息语义，不扩散到主按钮、导航选中和大面积页面背景。

### 5.2 目标基础色

以下为冻结规范值。根目录种子试用主入口已完成核心色板迁移；历史 CSS 层仍需按任务范围渐进收敛，不能据此假设所有旧选择器已经完成治理。

| Semantic Token | 目标值 | 用途 |
| --- | --- | --- |
| `--color-canvas` | `#FFFFFF` | 主页面画布和内容底色 |
| `--color-surface` | `#FFFFFF` | 主要内容面、表格、表单、弹窗 |
| `--color-sidebar` | `#FAFAFA` | 桌面侧栏，接近白色的纯中性浅灰 |
| `--color-surface-subtle` | `#F8F8F8` | 筛选栏、次级分组、轻提示 |
| `--color-selected` | `#F5F5F5` | 导航、分段控件和行 Hover / Selected |
| `--color-ink` | `#161616` | 主文字、核心数字 |
| `--color-ink-secondary` | `#666666` | 正文说明、次级信息 |
| `--color-ink-muted` | `#8A8A8A` | 时间、来源、占位和禁用信息 |
| `--color-border` | `#EEEEEE` | 普通分隔线和内容边界 |
| `--color-border-control` | `#E5E5E5` | 输入框、按钮和筛选控件边界 |
| `--color-border-strong` | `#DCDCDC` | 强分隔、表头和选中附近边界 |

当前原生入口的运行时映射：

| 规范 Token | 当前 CSS Token |
| --- | --- |
| `--color-canvas` | `--bg-page`、`--bg` |
| `--color-surface` | `--bg-card`、`--surface` |
| `--color-sidebar` | `--sidebar-bg` |
| `--color-surface-subtle` | `--bg-muted`、`--surface-muted` |
| `--color-selected` | `--brand-soft`、`--primary-soft` |
| `--color-ink` | `--text-primary`、`--ink` |
| `--color-ink-secondary` | `--text-secondary`、`--muted` |
| `--color-ink-muted` | `--text-muted`、`--subtle` |
| `--color-border` | `--border`、`--line` |
| `--color-border-control` | `--border-control` |
| `--color-border-strong` | `--border-strong`、`--line-strong` |

新增组件使用规范 Token 语义；现有原生入口在完成 CSS 层合并前可继续使用上述映射，但不得建立新的别名。

### 5.3 品牌与操作色

| Semantic Token | 目标值 | 用途 |
| --- | --- | --- |
| `--color-brand` | `#111111` | 品牌识别、主操作、当前导航强调 |
| `--color-brand-hover` | `#2A2A2A` | Primary Hover / Active |
| `--color-brand-soft` | `#F5F5F5` | 选中、Hover 和弱品牌背景 |
| `--color-on-brand` | `#FFFFFF` | 品牌色上的文字和图标 |
| `--color-focus-ring` | `#111111`（约 `42%` 透明度） | 键盘焦点环 |

蓝色不得作为全局 Primary Button、导航选中或品牌背景。旧金融蓝和电商蓝仅视为历史实现值，迁移后不得继续作为长期 Token 使用。

### 5.4 金融和系统语义色

| 语义 | 目标值 | 使用方式 |
| --- | --- | --- |
| 正收益 / 正贡献 | `#168A5B` | 数字、图表线、小面积浅底 |
| 负收益 / 负贡献 | `#D64545` | 数字、图表线、小面积浅底 |
| 成功 / 已完成 | `#168A5B` | 保存、导入、校验成功 |
| 警告 / 待处理 | `#D87900` | 过期、待确认、人工检查 |
| 风险 | `#D85B24` | 集中度、回撤等风险状态 |
| 错误 / 阻断 | `#D64545` | 导入失败、校验失败、无法计算 |
| 信息 / 数据序列 | `#2764E7` | 来源、解释、图表主序列；不得升级为品牌色 |

规则：

- 当前产品统一采用“绿色表示正收益，红色表示负收益”；
- 市场涨跌的本地化红绿习惯不与组合收益语义混用；当前阶段不另建第二套涨跌色；
- 正负数字必须保留 `+` / `-`；
- 大面积背景不使用高饱和红绿；
- 风险与错误分离：风险是需要关注，错误是流程阻断；
- 状态色必须配合文字、图标或符号。

### 5.5 图表色板

图表采用明亮、清晰、可区分但不过度荧光的色板。分类色只进入图表、图例和对应数据标记：

| Token | 目标值 | 建议语义 |
| --- | --- | --- |
| `--chart-1` | `#2764E7` | 主序列、基金或第一分类 |
| `--chart-2` | `#35A7E8` | 数字资产或第二分类 |
| `--chart-3` | `#20A67A` | 股票或第三分类 |
| `--chart-4` | `#F28A1A` | 现金或第四分类 |
| `--chart-5` | `#8B5CF6` | 第五分类 |
| `--chart-6` | `#E84A5F` | 第六分类 |
| `--chart-grid` | `#EEEEEE` | 网格线 |
| `--chart-axis` | `#DCDCDC` | 轴与分隔 |
| `--chart-muted` | `#777777` | 图表辅助文字 |

同一资产类别必须在全站保持一致色彩。分类色不得取代正负贡献色。缺失、未归因和待确认使用灰色或暖色，不使用正常品牌色。

### 5.6 深色模式

深色模式可以保留，但当前种子版本的视觉冻结与截图验收以浅色模式为主。

要求：

- 深色模式只能通过 Semantic Token 映射实现；
- 不能简单反转浅色颜色；
- 主要文字对比度至少满足 4.5:1；
- 图表线与背景至少满足 3:1；
- 未完成独立视觉验收前，不得写成已经完全支持。

## 6. 字体与数字

### 6.1 字体家族

界面正文统一使用系统无衬线字体：

```css
-apple-system,
BlinkMacSystemFont,
"SF Pro Display",
"Inter",
"Segoe UI",
Roboto,
Helvetica,
Arial,
"PingFang SC",
"Microsoft YaHei",
sans-serif
```

规则：

- 中文和英文正文使用同一系统无衬线体系；
- 金融数字启用 `font-variant-numeric: tabular-nums`；
- 核心金额和数字列可以使用当前数字字体栈：`"DIN Alternate", "Roboto Mono", "SFMono-Regular", ui-monospace, Consolas, monospace`；
- 数字字体只用于金额、收益率、价格和表格数字，不扩散到标题、正文、按钮和导航；
- 不提供 Serif、Mono、Rounded 等全局品牌字体变体；
- 代码、证券标识或技术字段需要等宽字体时，必须是局部且有明确语义；
- 中文正文不使用负字距。

### 6.2 字号体系

| 角色 | 桌面字号 / 行高 | 移动字号 / 行高 | 字重 |
| --- | --- | --- | --- |
| 核心金额 | `40 / 48px` | `32 / 40px` | `600–700` |
| 页面标题 | `24 / 32px` | `20 / 28px` | `600` |
| 区块标题 | `18 / 26px` | `17 / 24px` | `600` |
| 小标题 / Card 标题 | `14 / 22px` | `14 / 22px` | `500–600` |
| 正文 | `14 / 22px` | `14 / 22px` | `400` |
| 表格正文 | `13 / 20px` | 不直接压缩为表格 | `400–500` |
| 标签 | `12 / 16px` | `12 / 16px` | `500–600` |
| 辅助说明 | `12 / 18px` | `12 / 18px` | `400–500` |

只允许 `400 / 500 / 600 / 700` 四档字重。不新增 `450 / 550 / 650 / 750 / 800 / 900`。

### 6.3 金额层级

关键金额应拆分语义层级，而不是把整串文字做成同一视觉重量：

```text
CNY（次级）  1,999,276.59（核心）
+28,451.59 · +1.44%（次级结果）
截至 2026-08-01 · 4 项价格待检查（辅助状态）
```

规则：

- 货币代码为次级信息，不得和金额同等放大；
- 核心金额尽量保持一行，移动端根据可用宽度缩放，不从货币代码后强制断行；
- 数字列右对齐；
- 同屏最多 1–2 个核心金额；
- 来源、口径和时间使用辅助层级，但不得低于 12px；
- `0`、缺失、无法计算和未提供必须有不同文案。

## 7. 间距、圆角、边框与阴影

### 7.1 间距

唯一基础间距比例：

```text
4 / 8 / 12 / 16 / 24 / 32 / 48
```

推荐用途：

| Token | 用途 |
| --- | --- |
| `4` | 图标与短标签微间距 |
| `8` | 紧凑元素、行内信息 |
| `12` | 控件内部、紧凑列表 |
| `16` | Card 内部、移动端区块 |
| `24` | 页面区块、桌面 Surface 内部 |
| `32` | 大区块分隔 |
| `48` | 页面章节或空状态留白 |

禁止为了局部“看起来刚好”大量新增 `13 / 17 / 21 / 27px` 等长期值。

### 7.2 圆角

| 角色 | 圆角 |
| --- | --- |
| 控件、输入框、Badge | `6px` |
| Card、Panel、Table 容器 | `6px` |
| Dialog、Drawer | `10–12px` |
| Pill、圆形按钮 | `999px`，仅在语义确实需要时 |

圆角用于表达组件边界，不用于让所有内容“可爱化”。同一层级不得混用多种圆角。

### 7.3 边框

- 普通边框：`1px solid var(--color-border)`；
- 强分隔：`1px solid var(--color-border-strong)`；
- 一个区域已经有背景或留白分隔时，不再增加边框；
- 禁止同一区域同时使用背景、边框、阴影和外描边制造四重层级。

### 7.4 阴影

- Canvas、Section、普通 Card 和 Table 默认无阴影；
- Popover 使用轻阴影；
- Dialog 和 Drawer 使用中等阴影；
- Hover 不通过突然增加大阴影表达；
- 禁止彩色阴影、发光、玻璃拟态和大面积背景模糊。

## 8. App Shell 与响应式

### 8.1 桌面端

适用宽度：`≥ 1024px`。

- 使用稳定左侧导航和单行顶栏；
- 左侧导航保留“图标 + 中文标签”，不使用纯图标作为默认正式形态；
- 顶栏高度建议 `56–64px`；
- 顶栏按顺序承载：页面标题、当前观察范围、主操作、金额隐藏、更多操作；
- 同步问题只显示紧凑摘要或状态入口，不在顶栏展开长文；
- 主内容最大宽度 `1360px`；
- 页面水平边距 `24px`；
- 页面区块间距 `24–32px`。

### 8.2 平板端

适用宽度：`641–1023px`。

- 导航可收窄，但必须保留 tooltip、可访问名称和清晰选中态；
- 双栏允许转为单栏；
- 表格优先保留关键列，次级字段进入展开区；
- 页面主操作不得和筛选、设置同等强调。

### 8.3 移动端

适用宽度：`≤ 640px`。

- 顶栏保持单行，建议高度 `56px`；
- 顶栏只保留品牌/页面标题、一个主操作和一个更多入口；
- “检查价格、设置、用户、导出”等操作不得纵向铺满首屏；
- 四个一级导航保持稳定，可使用底部导航或紧凑横向导航；
- 主导航最多 4 项：总览、资产、分析、复盘；
- 页面水平边距 `16px`；
- 触控目标不小于 `44 × 44px`；
- 核心金额和核心状态必须在首屏可见；
- 宽表格转换为移动端资产行、摘要 + 展开或受控横向滚动；
- 固定导航必须为内容预留安全空间。

### 8.4 全局观察范围

账户、组合、时间范围和计价货币属于观察范围，不属于单个卡片的局部装饰。

规则：

- 同一种范围控件在总览、资产和分析页保持位置与样式一致；
- 页面返回时保留范围、筛选和滚动状态；
- 范围变化必须明确影响哪些数字和图表；
- 当前未实现的全局范围能力不得仅通过视觉规范写成已实现事实。

## 9. 公共组件

### 9.1 Surface、Panel 与 Card

#### Surface

用于需要从 Canvas 中形成独立内容面的区域，例如主表格、表单、Dialog 内容。

#### Panel

用于承载一个完整任务或数据问题，例如趋势、资产配置、导入预览。Panel 可以有边框，但内部子区块不得继续全部 Card 化。

#### Card

仅用于：

- 重复实体列表项；
- 独立可点击对象；
- 需要独立状态、展开或操作的内容；
- 少量关键指标。

禁止：

- 仅为标题和一段文字创建 Card；
- 指标 Card 套在 Panel 中，再套一层页面 Card；
- 为不同页面创建 `home-special-card`、`analysis-new-card` 等长期变体；
- 通过统一选择器把所有业务容器强制变成同一种 Card。

### 9.2 Button

| 类型 | 视觉 | 使用场景 |
| --- | --- | --- |
| Primary | 黑底、白字 | 添加、保存、确认导入等当前主任务 |
| Secondary | 白底、浅边框、深色字 | 取消、导出、检查价格 |
| Ghost | 无固定底色、Hover 浅底 | 工具栏和次级操作 |
| Text | 无边框、黑色或次级深色文字 | 查看来源、查看全部、下钻 |
| Danger | 白底红字或红色边框 | 删除、清空、不可逆操作 |

规则：

- 桌面高度 `36–40px`；移动高度至少 `44px`；
- 一个页面或任务步骤最多一个 Primary；
- Loading 时禁用重复提交并显示进度；
- Disabled 必须同时使用语义属性、视觉弱化和不可点击状态；
- 危险操作与普通操作空间分离；
- 图标按钮必须有 `aria-label` 和 tooltip；
- Hover、Pressed、Focus 不得改变组件尺寸或导致布局跳动。

### 9.3 Segmented Control 与筛选

- 用于少量互斥视图或时间范围；
- 选中态通过背景、字重和必要的边界共同表达；
- 不用多个独立 Primary Button 模拟筛选；
- 移动端可横向滚动，但不得折成多行按钮墙；
- 时间范围命名在全站保持一致。

### 9.4 Input 与 Form

- 桌面控件高度 `38–42px`；移动端至少 `44px`；
- 每个输入框有可见 Label，不以 Placeholder 代替；
- 金额、价格、数量、汇率明确单位、币种、精度和时间语义；
- 错误紧邻字段展示，格式为“问题 + 原因 + 修正方式”；
- 提交失败后聚焦第一个错误字段；
- 长表单按“资产、账户、数量价格、费用税费、时间来源”分组；
- 有未保存内容的 Dialog 或 Drawer 在关闭前确认。

### 9.5 Table 与高密度列表

- 资产、交易、归因和导入预览优先使用 Table；
- 第一列左对齐，数字列右对齐；
- 表头 `12px`，正文 `13px`；
- 行高根据内容保持紧凑，普通桌面数据行建议 `48–56px`；
- 行 Hover 只使用浅背景，不改变字号、边框或列宽；
- 可点击行提供稳定 Hover、Focus 和箭头/操作提示；
- 排序状态使用 `aria-sort`；
- 价格来源和时间放在对应数值下方，而不是独立占用大量列；
- 移动端保留资产名称、关键金额和状态，次级字段进入展开。

### 9.6 Badge 与 Status

Badge 只用于短状态和分类，不用于承载解释段落。

统一语义：

- `neutral`：类别、账户、市场；
- `info`：来源、联网、解释；
- `success`：已完成、同步成功；
- `warning`：过期、待确认、估算；
- `danger`：失败、阻断；
- `risk`：集中度、回撤等风险。

不得同时存在 `good / ok / positive / success` 等同义状态体系。状态 Badge 必须包含文字，不能只显示色点。

### 9.7 Empty、Loading、Error 与 Recovery

#### Empty

包含：当前为空的事实、为什么为空、一个合理下一步。不得默认注入正常 Demo 数据掩盖空状态。

#### Loading

超过约 300ms 的加载显示 Skeleton 或进度；占位应预留空间，避免布局跳动。

#### Error

说明发生了什么、影响什么、用户可以怎么恢复。不得只显示“失败”或静默吞掉错误。

#### Recovery

导入、恢复、删除和清空必须有预览、确认、取消或撤销路径，具体规则以数据与恢复文档为准。

### 9.8 Dialog、Drawer 与 Popover

- Dialog 用于阻断确认和需要集中注意力的短任务；
- Drawer 用于不离开当前上下文的录入或详情；
- Popover 用于轻量工具和解释；
- 不用 Modal 承载主导航；
- 均提供明确关闭入口和 Escape 路径；
- Dialog 建议圆角 `12px`，普通内容内边距 `24px`；
- 背景模糊只用于表达模态层级，不作装饰。

### 9.9 Icon

- 全站使用同一套 SVG 线性图标语言；
- 同一层级保持一致尺寸、线宽和圆角感；
- 不使用 Emoji 作为结构性图标；
- 不混用填充、线性、平台 Emoji 和字符图标；
- 图标服务于识别和操作，不用于填满空白；
- 图标视觉尺寸可以小于触控区域，但操作区域必须满足可访问要求。

## 10. 数据可视化

### 10.1 总体规则

图表用于解释：

- 组合价值和趋势；
- 资产分布；
- 变化归因；
- 贡献与拖累；
- 数据质量和风险。

图表必须显示或可访问：

- 时间范围；
- 计价货币和单位；
- 数据来源和更新时间；
- 缺失、估算或演示状态；
- 精确值的 Tooltip 或数据表替代。

不得添加仅为“看起来像金融产品”的装饰图表。

### 10.2 图表类型

| 问题 | 推荐 | 避免 |
| --- | --- | --- |
| 总资产趋势 | 细折线 + 极浅面积 | 厚重渐变、3D、发光线 |
| 收益趋势 | 折线，零轴清晰 | 不可解释双轴图 |
| 变化归因 | 瀑布图、横向条形图 | 用饼图解释变化原因 |
| 贡献排行 | 正负横向条形图 + 数值 | 只用颜色表达 |
| 资产分布 | 条形、简洁环图、必要时 Treemap | 超过 5 类的饼图 |
| 数据质量 | 状态列表、轻量进度 | 仪表盘式夸张评分 |

### 10.3 趋势图

- 趋势图和总资产可以构成同一个连续主视觉区域；
- 网格线低对比，不与数据竞争；
- 时间范围控件靠近图表；
- 面积填充透明且克制；
- 移动端减少刻度，不旋转或拥挤标签；
- 价格缺失或推导历史必须在图表内外明确标识。

### 10.4 分布图

- 类别不超过 5 项时可使用简洁环图；
- 类别较多时优先使用排序条形图；
- 图例靠近图表并直接显示比例；
- 不同页面的同一类别保持同色；
- 图表必须配合数据表或可访问摘要。

## 11. 数据可信与隐私表达

### 11.1 数据状态层级

数据状态分为：

1. 正常同步；
2. 手动填写；
3. 估算或成本价兜底；
4. 过期；
5. 缺失；
6. 同步失败；
7. 无法计算。

这些状态不得合并为一个模糊的“异常”。

### 11.2 状态位置

- 指标级状态紧邻指标；
- 资产级状态位于资产行或详情；
- 页面级摘要进入紧凑数据健康入口；
- 隐私和数据边界的完整说明进入设置、说明页或首次相关场景；
- 页脚可保留简短边界说明，但不得与页面主体重复长文。

### 11.3 金额隐藏

总览和包含私人金额的主要页面应支持金额隐藏，便于截图和公共环境使用。

要求：

- 隐藏状态对当前页面一致；
- 图表 Tooltip、表格和摘要不能泄漏被隐藏金额；
- 图标按钮有明确 Label；
- 是否持久化隐藏偏好由产品和隐私规则另行确认，不由视觉规范决定。

## 12. 页面应用规则

### 12.1 总览

唯一视觉主角：整体资产状态。

优先级：

1. 总资产、区间变化和数据状态；
2. 总资产趋势；
3. 账户与主要持仓；
4. 资产配置与数据健康；
5. 最近交易；
6. 复盘入口。

规则：

- 总资产和趋势形成连续主区域，避免多层 Card；
- 同步状态板不与总资产同等突出；
- 最近复盘不占据首次可信资产视图的核心位置；
- 数据问题显示数量和影响，详细修复进入对应入口；
- 首屏只有一个 Primary Action。

### 12.2 资产

唯一视觉主角：可维护、可核对的资产台账。

- 资产和持仓优先使用高密度表格；
- 名称、代码、市场、账户和数据状态层级稳定；
- 当前价格下方显示来源与时间；
- 缺失价格可直接进入补录或来源查看；
- 录入采用 Drawer、Dialog 或明确页面流程，但全站保持一种主要模式；
- 导入必须先预览错误、重复和影响，再确认写入。

### 12.3 分析

唯一视觉主角：资产变化原因。

页面围绕三个问题：

1. 这段时间为什么变了；
2. 哪些资产贡献或拖累最大；
3. 哪些风险和数据问题需要检查。

- 顶部保持时间和观察范围；
- 核心展示净投入、价格、汇率、分红、费用和未归因差异；
- 未归因差异始终显示；
- 异常项必须提供补价格、补汇率、查看交易或写复盘等下一步；
- 不重复总览页已有的装饰性分布图。

### 12.4 复盘

唯一视觉主角：用户自己的事实、判断和后续验证。

- 使用安静的笔记工具式布局；
- 列表突出标题、关联资产、日期和状态；
- 正文有更舒展的阅读宽度，但证据和关联信息保持结构化；
- 默认私有或草稿，公开操作处于次级位置；
- 不做社交动态流、收益榜或 AI 自动裁决。

### 12.5 设置、备份与恢复

- 设置按用户目标分组，不按技术模块堆叠；
- 私人数据、联网行情、导出备份和恢复边界使用准确文案；
- 高风险操作与普通设置视觉隔离；
- 删除、清空、恢复和导入显示影响范围和回退方式；
- 不用成功绿色掩盖尚未验证的数据结果。

## 13. 文案与语气

界面文案遵循：事实优先、短句、明确影响、给出下一步。

推荐结构：

```text
发生了什么 → 影响什么 → 可以怎么处理
```

示例：

- “4 项价格未能更新，当前仍使用最近一次有效价格。可重新同步或手动填写。”
- “该历史曲线包含演示估算，不代表真实历史净值。”
- “恢复将覆盖当前浏览器中的资产数据，请先导出备份。”

禁止：

- “稳赚”“跑赢必备”“智能荐股”“买入信号”；
- “AI 已为你找到最佳机会”等无法验证的能力表达；
- 用“Oops”“太棒了”等轻佻语气处理数据丢失或金融错误；
- 只说“出错了”而不给影响和恢复路径。

## 14. 动效与交互反馈

- 常规 Hover、Focus、展开和内容切换使用 `150–200ms`；
- 复杂 Dialog 或 Drawer 进入不超过 `300ms`；
- 退出时间短于进入时间；
- 只动画 `opacity` 和 `transform`，避免通过宽高变化造成布局抖动；
- 动效表达原因与结果，不做页面装饰性批量入场；
- 用户操作后在 100ms 内提供按压或状态反馈；
- 支持 `prefers-reduced-motion`；
- 动画不可阻断用户输入，也不能掩盖数据加载状态。

## 15. AI 玩具感反模式

以下模式禁止进入正式 UI：

- 页面标题下自动生成一段泛化“AI 洞察”；
- 每个指标都使用独立圆角卡片、彩色图标和浅色渐变；
- 同一页面出现多个主按钮；
- 为填补空白添加无决策价值图表；
- 使用 Emoji 作为导航、设置、风险或状态图标；
- 大面积蓝紫渐变、玻璃拟态、发光描边和彩色阴影；
- 过度胶囊化所有筛选、标签和按钮；
- 使用“智能、专业、深度、洞察”等抽象词代替真实数据口径；
- 页面进入时所有 Card 依次飞入；
- 用插画掩盖错误、空数据或恢复问题；
- 为单个页面追加新的 `final / polish / v2 / special` 覆盖样式。

## 16. CSS 与组件治理

### 16.1 新增规则

新增 UI 前必须检查：

1. 是否已有可复用组件；
2. 是否已有 Semantic Token；
3. 是否属于公共模式；
4. 是否会造成页面专用长期规则；
5. 是否需要更新本文档。

### 16.2 禁止覆盖层继续增长

禁止新增以下性质的长期文件：

- `final.css`；
- `new-polish.css`；
- `temporary.css`；
- `page-v2.css`；
- 仅通过后加载覆盖前一轮样式的全局补丁文件。

发现视觉不一致时，优先级是：

```text
确认规范 → 修正 Token → 修正公共组件视觉 → 删除失效颜色覆盖
```

不得优先在 `app.css` 末尾继续追加一轮覆盖。页面布局调整不属于当前视觉冻结范围，必须单独立项。

### 16.3 原生与 React 入口

- 当前根目录原生 JavaScript MVP 是种子试用主体验候选；
- React 是长期演进方向，不作为当前 UI 任务的默认替换方案；
- 两个入口共享品牌、Token 语义、组件状态和页面层级；
- 不在两个入口分别发明颜色、字体和状态系统；
- 业务规则和金融逻辑不得因视觉迁移而复制到 UI。

### 16.4 当前视觉迁移顺序

推荐顺序：

1. 基础与语义 Token；
2. App Shell 的颜色和表面层级；
3. Button、Surface、Status、Segmented Control 的视觉状态；
4. 图表色、图例和表格分类标记；
5. 页面专用旧颜色迁移到公共 Token；
6. 删除已经失效的颜色覆盖规则；
7. 在 `390px / 768px / 1280px` 下确认没有布局回归。

迁移必须保持可审查 diff，不得以视觉统一为理由顺带重构业务逻辑、DOM、信息顺序或响应式布局。导航重构、卡片合并和页面重新排版属于独立任务。

## 17. 视觉验收标准

每次 UI 任务至少检查 `390px / 768px / 1280px`。

本节包含长期目标。当前颜色与视觉换肤任务只验收视觉 Token、一致性、对比度和无布局回归；它不自动授权修复已有页面结构问题。

### 17.1 页面层级

- 用户 5 秒内能指出页面核心数字或核心任务；
- 每页只有一个视觉主角；
- 每页或任务步骤最多一个 Primary Action；
- 首屏主要 Surface 不超过 3 个；
- 不存在 Card 套 Card；
- 说明文字不与主数据竞争。

### 17.2 一致性

- 使用既有 Token；
- 字体和字号角色一致；
- 图标来自同一视觉语言；
- 状态语义没有同义重复；
- 相同范围、时间和操作控件跨页面一致。

### 17.3 金融可信

- 金额、币种、时间和范围明确；
- 正负、缺失、估算、手动、过期和失败可区分；
- 关键数字附近有来源或状态入口；
- 图表有单位、范围、状态和数据表替代；
- 页面不构成投资建议，不承诺收益。

### 17.4 响应式与可访问性

- 移动端顶栏不堆叠成按钮墙；
- 390px 无非必要横向滚动；
- 触控目标至少 `44 × 44px`；
- 键盘焦点清晰；
- 正文对比度至少 4.5:1；
- 图形和大图标对比度至少 3:1；
- 状态不只依赖颜色；
- 动效尊重 Reduced Motion。

### 17.5 实现质量

- 没有新增全局覆盖层；
- 没有页面专用重复组件；
- 没有散写未经批准的长期视觉值；
- 相关旧规则在任务范围内被收敛，而不是继续叠加；
- 浏览器级视觉检查与改动范围匹配。

## 18. 规范变更流程

以下变更需要产品负责人确认：

- 品牌色和整体视觉调性；
- 全局字体体系；
- 一级导航结构；
- 核心页面信息优先级；
- 公共组件的语义变化；
- 私人数据、风险和行情状态的表达边界。

普通组件细节可以在不改变上述规则的前提下渐进优化。若实现与本文档不一致，必须明确记录为：

- 已符合；
- 迁移中；
- 历史实现，待收敛；
- 经批准的例外。

不得通过新增页面规范绕过本文档。任何长期例外都应回到本文件评审，而不是散落在页面 CSS 或 PRD 中。

## 19. 最终原则

Asset Trail 的精致感不来自更多效果，而来自更少且更稳定的规则：

> 一个视觉主角、一个主操作、一套 Token、一种组件语言、一条可信证据链。

所有新的 UI 变化都应该增强这套系统，而不是创造新的视觉体系。
